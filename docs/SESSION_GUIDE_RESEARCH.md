# Arsip riset sesi merchant ShopeePay

> Catatan historis sebelum rilis login browser. **Bukan panduan penggunaan saat ini.** Impor token manual sudah dipensiunkan. Gunakan [Login ShopeePay](SHOPEE_CONNECT.md). Isi di bawah merekam riset lama, bukan fitur/alur aktif.

**Portal login resmi ada: <https://partner.shopee.co.id/>. PayGate saat ini mengimpor sesi merchant, bukan menjalankan login password/OTP Shopee.** Token sesi adalah kredensial akses setelah login, bukan password, OTP, atau API key yang dibuat sendiri. Jangan mengirimkannya ke chat.

Pemeriksaan GET publik portal berhasil: HTTP 200 setelah redirect ke `https://partner.business.accounts.shopee.co.id/authenticate/login/` dengan judul **Shopee Partner**. HTML meminta JavaScript; pilihan login yang tampil, keberhasilan password/OTP, dan ketersediaan token `B:` pada akun nyata **belum diverifikasi**. Sumber library tidak resmi bukan bukti API login resmi tersedia untuk PayGate.

## Lima langkah

1. **Login sendiri di portal resmi.** Buka <https://partner.shopee.co.id/> di browser pribadi. Ikuti metode login yang benar-benar ditampilkan, termasuk password, OTP, atau verifikasi bila diminta. Masukkan semuanya hanya di situs resmi, bukan PayGate atau chat. Pilih merchant/outlet milik sendiri yang memiliki layanan ShopeePay aktif. Login akun pembeli pribadi atau sesi yang hanya tersedia di aplikasi tidak otomatis menjadi sesi merchant kompatibel.

2. **Periksa trafik yang dibuat portal sendiri.** Di browser desktop buka DevTools → **Network**, lalu buka halaman riwayat transaksi ShopeePay melalui navigasi normal portal. Cari `get-transaction-list`. Target yang cocok dengan adapter PayGate adalah `https://shopeepay.shopee.co.id/merchant/v1/partner-web/get-transaction-list`. Jangan membuat request lewat Console, replay request, “Copy as cURL”, atau mengekspor HAR. Bila portal tidak membuat request tersebut, jalur pengambilan ini belum terbukti tersedia untuk akun itu.

3. **Cari token pada Payload, bukan mengasumsikan header Authorization.** Pada request tersebut, periksa **Payload / Request Payload → `data.metadata.token`**. Implementasi yang diaudit menaruh token di JSON body; header `X-Token` justru bernilai string kosong. PayGate mengharuskan token asli berawalan **`B:`**. Jika nilai itu memang terlihat, salin hanya nilainya secara lokal untuk kolom token di instance PayGate milik sendiri yang tepercaya. **Jika tidak ada token `B:`, berhenti: jangan menambahkan awalan `B:`, mengubah token lain, membongkar cookie acak, atau mengambil token aplikasi pembeli.** Jalur ini bersyarat; riset tidak membuktikan browser saat ini selalu memperlihatkannya.

4. **Ambil ID merchant dan outlet dari data akun yang sama.** Pada respons transaksi yang sudah diterima portal, pasangan `data.list[].merchantId` dan `data.list[].storeId` menunjukkan scope transaksi. Cocokkan dengan merchant/outlet yang dipilih; jangan mengambil baris outlet lain. Jika respons transaksi kosong, sumber yang diaudit mengenali `data.merchantId` pada respons profil `GetUserInfo` dan `data.list[].storeId` beserta `storeName` pada respons `get-store-list`. Periksa hanya jika request itu sudah dibuat navigasi resmi; jangan memanggil endpoint sendiri. Masukkan ke PayGate sebagai `merchant_id` dan `store_id`, berupa digit positif tanpa nol awal. Jangan memakai nomor HP, nama toko, ID pembeli/staf, atau `businessId` token. Jika pasangan ID tidak dapat dipastikan, hentikan impor.

5. **Lengkapi impor secara lokal, jangan menganggapnya sudah terhubung.** Gunakan `qris_static` dari QRIS resmi merchant/outlet yang sama; QRIS bukan pengganti token. Jangan menyalin seluruh cookie, HAR, respons berisi data pelanggan, atau telemetri perangkat. Simpan hanya pada instance yang Anda kelola dengan akses terbatas. Validasi format lokal tidak membuktikan Shopee menerima sesi, dan batas kedaluwarsa lokal tidak memperpanjang sesi provider. Pengujian koneksi nantinya merupakan request berautentikasi tersendiri, di luar riset ini. Jika sesi ditolak atau portal meminta verifikasi, selesaikan melalui kanal resmi; jangan meniru perangkat/aplikasi atau melewati challenge.

## Bukti dan batas

- **PayGate, `/root/paygate/src/services/provider.js:29–40,138–150`:** token Shopee wajib `B:`; merchant/store berupa string ID numerik positif; `qris_static` diperlukan. `:219–243` mengirim POST dengan `data.metadata.token`, `X-Token: ""`, kemudian mencocokkan `merchantId`/`storeId` respons secara lokal. ID tersebut bukan parameter scope pada body request feed ini. `:79` memakai `credentials: "omit"`; cookie browser tidak diimpor oleh adapter ini.
- **Sumber tidak resmi dipin:** `/root/shopeepay-research/merchantid`, `git rev-parse HEAD` menghasilkan `1fa55b3e1024861ef74968f9cdb1bb1bfb899fea`. `src/providers/shopee/transactionFeed.ts:101–120` dan `api.ts:212–229` menguatkan transport token pada body feed. **Header `X-Merchant-Token` ada untuk API partner/profil**, menurut `api.ts:180–201` dan `merchantClient.ts:69–89`; itu berbeda dari header feed transaksi. Jangan menyuruh pengguna mencari bearer header pada feed.
- **Asal ID:** `merchantClient.ts:25–46,69–99,129–153` mendefinisikan field profil/store. `transactionFeed.ts:23–34,200–206` memuat dan mencocokkan kedua ID transaksi. `authClient.ts:512–516` menjelaskan bahwa `businessId` token adalah ID klien SSO, bukan ID merchant.
- **Tidak ada tombol ekspor resmi terverifikasi.** `docs/shopee/sessions.mdx:46–53` membahas metode library `exportSession()`, bukan tombol di portal. Sumber `token.ts:40–80` membaca kredensial dari cookie dashboard, tetapi bukan bukti bahwa semua sesi mempunyai token `B:` yang cocok. Panduan ini sengaja tidak mengarahkan ekspor/dekode cookie.
- Mengamati request milik sendiri melalui DevTools tidak memerlukan peniruan aplikasi. Namun akses tersebut **tidak membuktikan izin provider untuk memakai ulang sesi di integrasi tidak resmi**, dan self-hosting tidak menghapus ketentuan provider. Bila token kompatibel tidak tersedia lewat alur resmi akun sendiri, belum ada jalur impor yang terbukti; gunakan dukungan/integrasi resmi merchant.
- Riset hanya membaca source terpilih dan melakukan GET publik portal. Tidak membaca `.env`, DB, sesi tersimpan, HAR, atau `deviceRisk.ts`; tidak mengirim OTP, login, telemetri, maupun request API berautentikasi. Penerimaan token live tidak diuji.
